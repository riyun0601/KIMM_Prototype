# KIMM Cyber Lab SW 사용성 평가

이 저장소의 5개 프로토타입을 한 Netlify 사이트로 배포합니다. 원본 앱의 소스와 설정은 빌드 과정에서 수정하지 않습니다. 빌드 스크립트가 각 앱을 `.kimm-build/`에 복사한 뒤 경로를 조정하고, 최종 파일을 `dist/`에 모읍니다.

## 배포

저장소 전체를 Git에 올려 Netlify 프로젝트와 연결합니다. 루트의 `netlify.toml`에 빌드 명령 `node scripts/build-all.mjs`와 게시 폴더 `dist`가 설정되어 있습니다. Node 버전은 `.node-version`의 24를 사용합니다. Netlify 빌드 중 각 앱의 잠금 파일에 따라 의존성이 자동 설치됩니다.

완성된 `dist/` 폴더를 Netlify에 직접 업로드하는 임시 배포도 가능합니다.

## 로컬 빌드

```powershell
node scripts/build-all.mjs
```

로컬에서 npm 설치가 제한되어 있고 CAD, FLOW, SYS의 `node_modules`가 이미 있을 때는 아래 검증 모드를 사용할 수 있습니다. CAM과 STRUCTURE는 CAD의 설치본을 임시로 재사용하므로 실제 배포 검증은 Netlify의 기본 빌드로 완료해야 합니다.

```powershell
node scripts/build-all.mjs --local
```

홈은 `/`, 앱은 `/cad/`, `/cam/`, `/flow/`, `/structure/`, `/sys/`에서 열립니다. `dist/`와 `.kimm-build/`는 Git에서 제외됩니다.

## VS Code에서 홈과 5개 프로그램을 함께 실행

프로젝트 루트 `KIMM_Prototype`의 터미널에서 실행합니다. Node.js 24를 권장합니다.

```powershell
node scripts/build-all.mjs
node scripts/serve.mjs
```

브라우저에서 http://127.0.0.1:4173/ 을 엽니다. 현재 PC의 기존 설치본을 사용하는 경우 첫 명령을 `node scripts/build-all.mjs --local`로 바꿀 수 있습니다. 소스 변경 후에는 다시 빌드해야 합니다. 서버 종료는 Ctrl+C이며, 다른 포트가 필요하면 실행 전에 `$env:PORT = "4174"`를 지정합니다.

루트에는 `package.json`이 없으므로 루트에서 `npm install` 또는 `npm run dev`를 실행할 필요가 없습니다. 기본 통합 빌드는 5개 앱의 잠금 파일을 사용하여 `.kimm-build/` 내부에서만 `npm ci`를 실행합니다. 각 원본 폴더에 별도로 npm을 설치할 필요가 없습니다. `--local` 모드는 기존 `KIMM-CAD`, `KIMM-FLOW`, `KIMM-SYS`의 `node_modules`를 사용하며 CAM·STRUCTURE는 CAD의 설치본을 재사용하므로 배포 빌드 대체용이 아닙니다.

개별 앱의 소스 개발 서버가 필요한 경우에만 `KIMM-CAD`, `KIMM-CAM`, `KIMM-FLOW`, `KIMM-STRUCTURE`, `KIMM-SYS` 중 해당 폴더에서 `npm.cmd ci`, `npm.cmd run dev`를 실행합니다. 각 Vite 서버는 그 앱 하나만 제공합니다. 홈 복귀를 포함한 사용성 평가와 배포 전 확인에는 위 통합 서버를 사용합니다.

### `Cannot GET /cam/` 원인

`/cam/`은 원본 `KIMM-CAM/` 폴더명이 아니라 통합 빌드가 만드는 `dist/cam/`의 URL입니다. 원본 루트를 Live Server 등으로 제공하면 이 경로가 없고 Netlify의 설정도 적용되지 않습니다. `scripts/serve.mjs`는 빌드된 `dist/`를 제공하며 앱별 직접 접속, 새로고침, 하위 URL을 처리합니다. Netlify에는 앱별 rewrite를 설정했고, 빌드 시 각 앱 HTML에 base 경로를 지정하여 하위 URL에서도 상대 경로 아이콘이 로드됩니다. 또한 기존 SYS 빌드 설정의 import 제거가 Windows CRLF 줄바꿈에서 실패하던 문제를 수정했습니다.

## 매뉴얼·설문·평가 완료

홈의 기존 아이콘 카드 아래에 `사용매뉴얼 [바로보기] [다운로드]`와 `사후 설문 바로가기`를 추가했습니다. 매뉴얼은 `manuals/`의 원래 PDF 이름을 유지하며 통합 빌드에 그대로 복사됩니다. 바로보기는 새 탭의 브라우저 PDF 뷰어를 사용하고 다운로드는 원본 파일명으로 저장합니다.

5개 프로그램 모두 실행 직후부터 오른쪽 하단에 `평가 종료 및 설문 응답하기` 버튼을 항상 표시합니다. 사용자가 자율적으로 튜토리얼을 수행하고 종료 시점을 선택합니다. 평가 완료 감지·결과 확인·버튼 활성화 조건은 없습니다.

버튼은 높이 56px, 기본 글자 크기 16px의 고정 오버레이입니다. 오른쪽/하단 기본 간격은 24px이며, 상태줄이나 기존 입력·조작 컨트롤과 겹치면 버튼만 위로 이동합니다. 앱별 기존 강조색 계열에 흰색 글자 대비를 확보했습니다. 기존 툴바·탭·작업 영역의 크기는 변경하지 않습니다.

한 번 클릭하면 프로그램에 해당하는 Google Forms를 새 탭에 열고 기존 탭을 메인 홈으로 이동합니다. 새 탭이 차단되면 평가 화면과 상태를 유지하며 재시도 링크, 복사 가능한 주소, 사용자가 선택하는 현재 탭 설문 링크를 제공합니다. 새 탭 재시도가 성공한 경우에만 자동으로 홈으로 이동합니다. 설문 주소와 공통 버튼 구현은 `evaluation.js`에 있습니다.

## Netlify 배포 확인

저장소 루트를 Base directory로 사용하고, Build command는 `node scripts/build-all.mjs`, Publish directory는 `dist`를 사용합니다. 추가된 `evaluation.js`, `scripts/serve.mjs`와 PDF 5개를 포함해 변경 파일을 Git에 추가해야 합니다. 특히 `manuals/`는 작업 시작 시 미추적 상태였습니다. 사이트 전체 공개 URL을 받으면 `/`, 5개 앱 경로, 한글 PDF 경로와 설문 링크를 다시 확인한 뒤 전달하세요. 배포된 사이트의 실제 검증은 로컬 빌드 검증과 별개입니다.

## 검증 기록 (2026-10-28)

- `node scripts/build-all.mjs --local`과 기본 `node scripts/build-all.mjs` 모두 5개 앱 빌드 성공. 기본 빌드는 각 잠금 파일로 `npm ci`를 수행했습니다.
- CAD·CAM·STRUCTURE의 `npm.cmd run check` 통과. FLOW·SYS에는 check 스크립트가 없어 빌드와 브라우저 실행으로 확인했습니다.
- 로컬 Edge에서 5개 앱의 직접 URL 접속, 새로고침 및 하위 URL 접근을 확인했습니다. 브라우저 JavaScript 오류와 정적 자산 응답 오류가 없었습니다.
- PDF 5개의 HTTP 응답이 원본 파일과 바이트 단위로 일치하고, PDF MIME·inline 헤더·부분 요청 및 원본 다운로드 파일명을 확인했습니다.
- 홈 설문 링크 5개와 완료 처리의 프로그램별 설문 주소, 새 탭, 현재 탭 홈 이동, 팝업 차단 시 안내와 링크 재시도를 확인했습니다. 외부 설문 응답은 제출하지 않았으며, 설문 서비스의 공개/로그인 권한 상태는 검증하지 않았습니다.
- 실제 UI 조작으로 CAD 스케치→회전→원→Pocket→4개 패턴, CAM Gravure 작업 삭제→3개 툴패스 생성, FLOW 계산→잔차→종료→Monitor, STRUCTURE 정적 단계→해석 결과→Circular 4→애니메이션, SYSTEM 내장 F8 모델→시뮬레이션→위치 그래프에서 평가 완료 버튼과 이동을 확인했습니다. 이 검사는 최종 단계 연결 검증이며, 모든 튜토리얼 수치 입력·모델 작성 과정을 전수 검증한 것은 아닙니다.
- 1440px 화면에서 기존 홈 카드의 위치·크기·배경·테두리가 변경 전과 일치했습니다. 320/390/768/1024px에서는 추가 링크가 겹치지 않는지 확인했습니다. 각 프로그램의 기존 CSS는 수정하지 않았습니다.
- 실제 Netlify 배포/공개 URL 검증은 수행하지 않았습니다. 배포 시 위 경로와 정적 파일 접근을 다시 확인해야 합니다.


## 종료 시점 재검증 (2026-10-29, 간소화 이전 기록)

PDF 5개의 마지막 페이지와 실제 상태 전환 코드를 대조했습니다. 화면 진입으로 사용자의 육안 확인까지 완료됐다고 간주하지 않습니다. 별도 확인 이벤트가 없는 프로그램은 기존 완료 버튼을 확인 동작으로 재사용하고, 확인 후 동일 버튼의 문구와 동작을 설문 응답으로 전환합니다. 중복 버튼은 추가하지 않았습니다.

- CAD: `phase === 'pattern'`, `patternCount === 4`, 편집 작업이 없는 상태에서 `최종 형상 확인 완료` 클릭을 받습니다. 패턴 생성만으로 설문을 표시하지 않으며, 다른 단계/편집으로 돌아가면 확인 상태를 초기화합니다.
- CAM: `toolpath.toggleVisible` 이벤트로 툴패스별 조작 여부를 기록합니다. 3개 모두 조작한 뒤 현재 시각화 이미지가 정상 로드된 상태에서 `툴패스 시각화 확인 완료` 클릭을 받아야 설문을 표시합니다. 툴패스를 재생성하거나 표시 상태를 변경하면 기존 확인을 재사용하지 않습니다.
- FLOW: `runState === 'terminated'`, `runProgress === 1`, `residualStarted`, Monitor 선택과 실제 첫 모니터의 `point-mon-1`/`Pressure` 설정을 확인합니다. 압력 그래프 캔버스가 생성된 뒤 `압력 그래프 확인 완료` 클릭을 받으며, 계산을 재시작하면 확인을 초기화합니다. 모니터가 없어 기본 이름만 표시되는 그래프는 완료로 인정하지 않습니다.
- STRUCTURE: 해석 실행 완료, Results 상태, 4개 원형 변환 적용 및 변환 창 종료를 확인합니다. Animation의 실제 재생 콜백에서 `progress === 1`에 도달한 때 설문을 표시합니다. 창 진입, 재생 전, 구간 종료 전 정지로는 표시하지 않습니다.
- SYS: 기존 시뮬레이션 완료 → Position Transducer 위치 출력 선택 → Plot Window 흐름 후 `위치 그래프 확인 완료` 클릭을 받습니다. 그래프 창을 닫거나 새 모델/시뮬레이션을 시작하면 확인을 초기화합니다.
